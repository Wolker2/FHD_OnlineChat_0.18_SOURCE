Проверки не заменяют запуск игры на Windows.
В каталоге SOURCE с Zig 0.13.0:
zig cc -target x86-windows-gnu -shared -O2 -fno-builtin -DFHD_TEST bridge.c overlay.c plugin_zig.def -luser32 -lgdi32 -lwinhttp -lshell32 -o tests_runtime018.dll
Python: pefile, unicorn, Pillow. Затем python QA/emulate018.py "C:\BuildA\Rangers.exe" "C:\BuildB\Rangers.exe".
Node с node:sqlite: node QA/server.test.mjs.
Эмулятор выполняет настоящий x86-код DLL с макетами WinAPI, D3D и сети. PNG строится из реальных вершин рендерера. Серверные тесты выполняют server.js 0.18, подставляя контекст DO/WebSocket и реальную SQLite.
Результаты и изображение записываются рядом со скриптами. Производственную DLL собирайте без FHD_TEST; тестовые экспорты в установочном файле отсутствуют.

В этой версии дополнительно инструментированы чтение INI, запись UTF-16, flush/replace, отказы диска и захват мыши. Дополнительно проверяются суточная очистка обоих каналов, отбрасывание вчерашней очереди, повторный reset, смена месяца, primary/backup, смена суток в скрытом меню.

Для проверок совместимости требуются оригинальные EXE, соответствующие SHA256 в compat_profiles.h; они не поставляются. Два пути передаются после имени скрипта. В рабочем каталоге при отсутствии аргументов используются upload/Rangers.exe и upload/Rangers(1).exe. Скрипт загружает их PE-образы в Unicorn, исполняет детектор/перехваты из тестовой DLL и три настоящих участка вызовов каждой сборки. WinAPI/D3D инструментированы, игровая сессия на Windows не запускается. compatibility_results.json отделяет эти результаты от реального игрового теста.

Дополнительные проверки имени используют настоящие mapped PE и TPlayer VMT соответствующего EXE, синтетический объект/UTF16-BSTR и настоящий код GetPlayer в эмуляторе. Покрыты загрузка старого сейва, новый несохранённый персонаж, ручное имя, nil/невалидный объект, недоступная память, длина/терминатор строки, гонка смены указателя, лимит частоты и отказ сигнатуры имени при работающей графической части. Не являются запуском настоящей игровой сессии.

Быстрая проверка изменённого UI и необходимых клиентских регрессий: python QA/emulate018.py без путей EXE. Для полного повторения неизменённых профилей/пилота передайте два EXE-пути, как указано выше. В этой версии выполнен быстрый режим, compatibility_results.json и анализы EXE/пилота переиспользованы из 0.17, не являются повторным игровым запуском. Показанные маски замка/шестерёнки восстановлены из настоящих вершин скомпилированной DLL.

Новые проверки видимости используют оба исходных PE в эмуляторе и настоящий encoded-player слот, с состояниями nil/TPlayer/недоступный объект. Проверяется отсутствие D3D-команд и захвата ввода в меню, возврат в игру, черновик/настройки/F12, однократное чтение класса на новый указатель. Основные UI-регрессии имеют явный mock активной сессии. Для этих проверок пути EXE по умолчанию upload/Rangers.exe и upload/Rangers(1).exe относительно рабочего корня; сами EXE в архив не включены.

Серверные тесты используют Node с node:sqlite и макеты DO, WebSocket, часов и alarm. Проверяются четыре схемы SQLite (sender/nick/обе/новая), миграция с сохранением сегодняшней истории, очистка в полночь, повтор alarm, пробуждение, переподключение, пропущенный alarm, изоляция PM и границы 23/25-часовых суток. Это не облачный end-to-end тест.
