Совместимость вынесена в compat_profiles.h. Профиль A: timestamp 0x68ECCC46, SizeOfImage 0x4D1000, device RVA 0x47A798, render RVA 0xC530D / 0xC5402 / 0xC560D. Профиль B: timestamp 0x6AC53B97, SizeOfImage 0x461000, device RVA 0x41302C, render RVA 0x3CAF19 / 0x3CB00E / 0x3CB1EF. Новые поля профиля A: EncodedPlayer RVA 0x47C19C, GetPlayer-инструкции RVA 0x38C07C, TPlayer VMT RVA 0x38BE5C, class name RVA 0x38BF52. Для B: 0x4100FC / 0x347300 / 0x347118 / 0x34720E. Эта проверка отделена от отрисовки: отказ имени не отключает DX9-перехват.

В ручном режиме нет чтений памяти. Таймер использует существующий фоновый heartbeat-поток, не кадры рендера. Резервный heartbeat остаётся раз в 20 секунд.

Уведомления 0.19: новый внутренний флаг Notifications=0/1 вне 80-байтового FHDChatPreferences. Значения, отличные от 1, выключают функцию; отсутствие ключа — 0. Сеть 0.20: g_failed_day теперь устанавливается только при явном HTTP 429. Обычные ошибки считаются отдельно: три подряд включают временный резерв на 60 секунд (GetTickCount, unsigned wrap-safe разность), затем heartbeat закрывает резерв для повторной попытки primary, даже если Receive не получает новых данных. Успешный hello обнуляет счётчик; forced reconnect при нике/пробе не считается ошибкой. Между попытками прежняя пауза 5000 мс. HTTP 429 до следующей UTC-даты сохранён как отдельная политика; точное происхождение любого конкретного 429 без лога/тела ответа не классифицируется.
heartbeat_step вызывается прежним потоком раз в секунду. Primary ping — точная строка {"type":"ping"}, каждые 10000 мс; отсутствие любых входящих данных 35000 мс вызывает close/reconnect. Backup сохраняет Phoenix heartbeat 20000 мс. Нет дополнительных таймеров/запросов на кадре и новых настроек. WinHTTP send/close/освобождение дескриптора сериализованы отдельным interlocked-флагом; UI при занятом флаге возвращает отказ, сохраняя черновик. Отправка в уже известное закрытое/ошибочное соединение запрещена.
Сервер 0.20: ctx.setWebSocketAutoResponse(new WebSocketRequestResponsePair('{"type":"ping"}','{"type":"pong"}')). Точные ping обслуживаются runtime без пробуждения DO; JS handler отвечает также на валидный JSON ping с иным форматированием без изменения last/rate/history/identity. Существующие SQLite/алармы/схемы/PM и namespace не менялись. Типы проверены по @cloudflare/workers-types 5.20261028.1 и официальной документации setWebSocketAutoResponse. Серверное автоэхо не является подтверждением сохранения пользовательского сообщения; пользовательские сообщения по-прежнему появляются в истории при серверной рассылке.
Журнал содержит HTTP и код WinHTTP при разрыве, плюс событие watchdog. Секреты/тексты пользовательских сообщений в эти строки не добавляются. Отдельный внутренний FHDChat_IsBackup позволяет UI явно показывать резерв; публичные экспорты и preferences ABI неизменны.
